# RAG / 知识库核查

> **证据状态**：已验证（运行清单与 API 审计未发现向量/RAG 服务，2026-11-24）｜代码推导（随包文档存在文件/知识类工具）｜待确认（未来若引入 RAG，其组件与配置）｜不适用（向量数据库、Embedding、Rerank 服务的运维——现网不存在）。
>
> 本文件的作用是**防止虚构配置**：不得编写不存在的向量库连接、索引重建或 Embedding 调参步骤。

## 1. 审计结论（已验证）

- `audit/architecture.md` 明确：未发现独立向量数据库或 RAG 服务；向量索引、Embedding、Rerank 服务均不在运行清单中 → **不适用/待确认**。
- `audit/dependencies.md`：未发现独立向量数据库、产品侧 Redis/MQ、K8s 产品负载。
- 主引擎五容器为 edge / server / docx-rewriter / onlyoffice / quse-gateway；Sandbox 引擎跑 Workspace/Browser；本地模型层为 GPUStack 网关 + 对话/生图/解析/决策模型，**无一被识别为向量或 RAG 服务**。

## 2. 现网"类知识"能力边界（代码推导）

- 平台提供文件/知识类工具与 Workspace 私有文件通道（0.9.1 起），但这是**文件存取与工作区能力**，不等同于向量检索 RAG。
- OXR（`:18094`）是文档解析（PDF/图片 → 结构化，vLLM，非 OpenAI 协议），属于解析服务，不是 Embedding/向量库。
- 模型 `laya` 是文本决策/安全防护（CPU），不是 Rerank 服务。
- 因此「文档解析」「知识类工具」「决策模型」都**不能**被改写为 RAG 组件。

## 3. 用户问到 RAG 时的标准答复

1. 说明审计事实：当前 0.9.3 运行实例未发现独立向量数据库/Embedding/Rerank 服务，相关运维**不适用**。
2. 若用户坚持某处存在 RAG：要求提供组件名、端口或配置路径；在取得证据前标**待确认**，不生成命令。
3. 不创建虚构的「向量库地址」「索引名」「重建索引 cron」「Embedding 模型配置」。
