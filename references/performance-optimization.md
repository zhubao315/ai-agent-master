# 性能优化

> **证据状态**：已验证（资源基线实测，2026-11-24）｜代码推导（随包文档 `deploy/capacity` 系列、`local-model-deploy/gpustack` 实测表）｜待确认（现场真实业务并发与推理配置；优化前后对比需实测）｜不适用（源码级性能剖析）。
>
> 优化前先量化水位，优化后按同一场景复测。生产变更默认只读 + 审批。

## 1. 先看瓶颈，再做优化（代码推导）

实测水位与瓶颈见 `resource-assessment.md`：OnlyOffice 转换逼近配额（瓶颈 1）、命令总线实例数 >600（瓶颈 2）、SQLite 写锁拐点约 200 写/秒（瓶颈 3，余量足）。**容量通常不由 GPU 决定**。

## 2. 组件级优化方向（代码推导）

- **OnlyOffice**：内存配额提到 4GB 以上；转换请求独立分池；保持内存 <85% 配额。转换峰值 CPU 88% / 内存 3.4GB（配额 4GB）。
- **命令总线**：注册实例 600 告警；中期心跳扫描分片；超时 30s→504，per-instance 120 命令/60s 限流。
- **Server**：CPU 峰值 71% / 内存 2.1GB（配额 2C/4GB）；关注异步队列（lease 15min、记录保留 30 天）与长上下文压缩阈值。
- **Workspace/Browser**：按并发任务数核算；隔离不可用时明确失败，不降级本机。

## 3. 模型 / 推理侧（代码推导，随包文档）

- 吞吐随同机其他负载波动 ±30%，不要拿瞬时峰值当容量。
- `qwen3.8-flash-next` 经网关由集群（:18086，weight 80）+ 独立实例（:18103，weight 20）分流，共 10 槽位；网关自动负载均衡，客户端无需再做。
- 长上下文同时抬高 TTFT 与显存：4.7K 输入首字 2.22s，47K 输入 24.2s；控制上下文长度与 `autoCompactTokenLimit`（≥32000，默认 160000）。
- 生图模型共用 GPU，请求实际串行；批量按模型分组提交，工具超时给到 1200s（跨模型换权重首个请求可达 5–8 分钟）。H3 有 GPU5 独占实例 `:18198`（2048² 4.9s），共卡冷跑 307s。
- 量化 / KV Cache / 并发槽位策略属**待确认**（无源码、未读启动参数），不得凭空调参。

## 4. 压测与验收门槛（代码推导）

必做场景：单用户基线、阶梯并发、稳态 30 分钟、突发流量、长上下文、故障注入、限流与过载。每级稳定 ≥5 分钟，取满足全部 SLO 的最大持续负载。

| 对象 | 门槛 |
|---|---|
| 浏览 | 每域 100 并发 P95 <500ms，错误率 0 |
| 管理接口 | 200 并发只读 P95 <800ms |
| 对话 | 流式首包 P95 <3s（模型目标 P95 TTFT <2s） |
| 文档 | 首屏 <5s，转换内存 <85% 配额 |
| 模型 | 目标路数 30 分钟成功率 >99% |
| 资源 | 目标负载峰值 <90% 配额 |

已有基线（随包文档）：100 并发混合浏览 P95 412ms；200 并发只读 P95 638ms；健康探针 P95 45ms；流式首包 P95 2.4s；文档编辑器冷 4.6s/热 1.8s。

## 5. 扩容触发（代码推导）

有效吞吐达已验证容量 80%；P95/P99 持续超 SLO 80%；队列增长 10 分钟；资源峰值 >90% 配额；命令总线实例 600；OnlyOffice 转换内存 85%；DB 写入接近 200/s。
过载顺序：限流 → 排队 → 背压 → 降优先级 → 降级模型 → 明确失败。

## 6. 本机特别约束（已验证）

- `/data` 已用 80%：日志、备份、缓存增长要有告警，写满无剩余容量。
- 多卡显存 >47GB：不在此机起新推理负载做压测（风险 R7）。
- 所有优化须在同一场景、同负载下复测并记录；无证据的性能结论标**待确认**。
