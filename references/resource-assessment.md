## 3. 并发分层与折算（代码推导）

业务并发 → 请求并发 → 模型并发 → 运行时并发，四层数值不同；客户说「30 并发」先确认是哪一层。

- 请求到达率 λ = U×r/60；在途 C = λ×W；模型请求率 Q = λ×p×m×(1+ρ)。
- 输出 Token/秒 R_out = Q×T_out，决定 Decode；R_in 决定 Prefill。
- 模型实例数 N = max(N_thr, N_con)，再受显存上限约束；单实例实测锚点 `G≈140 tok/s`（随包文档）。
- 长上下文同时抬高 TTFT 与显存：4.7K 输入首字 2.22s，47K 输入首字 24.2s。

五档参考（在线用户）：入门 ≤10 / 小型 10–30 / 中型 30–100 / 大型 100–200 / 高可用 200–300；300 以上转 k8s 与外部数据库（均为随包文档目标/推算，非本机合同）。

## 4. 沙箱 / 浏览器（代码推导）

- 按**同时执行任务数**核算，不按在线用户数。
- 沙箱默认限额 1 核 1GB 128 进程；最小 1 核 2GB/10GB，推荐 2 核 4GB。
- 浏览器最小 0.5 核 1GB，推荐 1 核 2GB 5GB。
- 隔离不可用时必须失败，不回退本机。

## 5. 扩容触发阈值（代码推导）

有效吞吐达已验证容量 80%；P95/P99 持续超 SLO 80%；队列增长 10 分钟；GPU/内存/CPU 峰值 >90% 配额；命令总线注册实例 600；OnlyOffice 转换内存 85% 配额；DB 写入接近 200/s；在线用户单域 300。

过载顺序：限流 → 排队 → 背压 → 降优先级 → 降级模型 → 明确失败。

## 6. 本机判定（结合风险登记册）

- 磁盘：`/data` 80%，留给备份/安装的空间有限 → 执行 `--full-backup` 前检查余量。
- GPU：多卡 >47GB 且利用率 0%（显存被权重常驻占用）→ 不新增推理负载做压测。
- 容量置信度：低。只有取得推理框架真实并发/量化/KV Cache 配置后才能给可用并发数；在此之前只报告资源基线，不承诺 SLA。
